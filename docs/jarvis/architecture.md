# Архитектура Jarvis

Rujarvis — самостоятельное приложение Electron. Он начинался как форк
[Interpreter Workstation](https://github.com/openinterpreter/interpreter-workstation),
но от его кода больше не зависит ни строкой: работу делают официальные CLI
Claude Code и Codex по подписке человека или Gemini CLI с его Google-аккаунтом, а экран, браузер и файлы агент
получает от собственного MCP-сервера Джарвиса.

```
  микрофон ─► app/voiceBridge.ts ─► прямые команды (клавиши, окна, программы) ──► сразу
                    │
                    ├─► разговор: живая сессия Claude Code, без неё — Codex или Gemini (jarvis/dialogue)
                    │        ├─ рычаги: завести / поправить / остановить работу
                    │        └─ руки на экране (jarvis/control/uiHands.ts): окно, вкладка,
                    │           кнопка, меню, клавиши, сайт, приложение Claude
                    │
                    └─► JarvisCore (jarvis/core.ts)
                          router ─► risk ─► tasks ─► BackendManager
                                                      ├─ Claude Code  + MCP рабочего стола
                                                      │               + хук красных линий
                                                      ├─ Codex        (песочница; экран — через сервер с проверкой)
                                                      ├─ Gemini       (без оболочки; запись — в папку задачи;
                                                      │                экран — через сервер с проверкой)
                                                      └─ локальная модель (если настроена)
```

Приложение (`app/`): трей, онбординг и настройки (`settingsWindow.ts`,
`ui/`), голосовой мост, оверлеи. Вид окон — три переключаемых вида и
светлая/тёмная тема из `ui/looks.css` и `look.ts`
(`docs/jarvis/design/2026-10-20-оформление-design.md`). Всё на диске — в одной папке
(`jarvis/setup/paths.ts`), язык — одна настройка (`jarvis/locale/`).

## Поток одной реплики

`JarvisCore.handleUtterance` выполняет ровно эту последовательность:

1. **Локальная проверка управляющих слов.** «Стоп», «отмена», «пауза»,
   «продолжай» обрабатываются синхронно, без модели и без сети. Ждать токены
   от большой модели, пока ассистент продолжает печатать в редакторе — самый
   быстрый способ потерять доверие пользователя.
2. **Маршрутизация.** `jarvis/router` определяет capabilities, backend, проект,
   риск и потолок разрешений. Правила детерминированы: без единой загруженной
   модели маршрутизация работает.
3. **Нормализация.** Приводит реплику к цели и ограничениям. Два инварианта
   держатся кодом, а не просьбой в промпте: нормализация может только *сужать*
   разрешения, и исходная реплика всегда доходит до сильного backend.
4. **Политика риска.** Классификация — чистая функция от конкретного действия.
   Текст модели может поднять класс, но никогда не понизить.
   Это первая проверка — по фразе. Вторая идёт на каждом вызове инструмента
   агентом (см. «Красные линии на инструментах» ниже).
5. **Отбор контекста.** Только то, чего касается эта реплика: релевантные
   записи памяти плюс состояние мира, если в реплике есть «это», «туда»,
   «продолжай». Полный дамп памяти в каждый запрос — это медленно, дорого и
   сбивает модель.
6. **Задача.** `TaskManager` запускает работу. Метод возвращается сразу: задача
   на пять минут не должна блокировать следующую фразу.
7. **Подтверждение голосом.** Строится из решения маршрутизатора — до того, как
   любая модель выдала первый токен. Оно никогда не утверждает, что работа
   сделана.
8. **Прогресс и результат.** Прогресс показывает действия, а не рассуждения.
   Экран получает полный ответ, голос — одно-три коротких предложения.

## Красные линии на инструментах

Фраза «разбери загрузки» безопасна, а `git push --force`, который агент
выполнит посреди этой работы по подсказке с прочитанной страницы, — нет.
Поэтому каждому запуску Claude Code даётся хук PreToolUse
(`jarvis/risk/gateHook.ts`, роль `gate` сборки `mcp.cjs`). Он переводит вызов
инструмента в действие для той же политики (`jarvis/risk/toolGate.ts`):

- команды оболочки — по шаблонам разрушительного и уходящего наружу;
- запись файла — по месту: системные папки опасны, `.claude`/`.codex` и данные
  Джарвиса чувствительны, рабочая папка, папка результатов и временная — обычны;
- кнопки браузера со словами оплаты и отправки, поля карт и паролей;
- запись навыка в общие навыки Claude Code, запуск исполняемого файла,
  перенос файла снаружи в папку результатов.

О чувствительном и опасном хук спрашивает человека голосом через файловый мост
(`jarvis/risk/gateBridge.ts`) и ждёт до минуты. Молчание, нечитаемый вызов,
любой сбой — отказ. Если хук поставить нельзя (нет `node` или сборки), агент
не получает оболочку, запись навыков и свою папку на запись.

Чего хук не видит: клик по координатам и нажатие элемента окна по номеру не
говорят, что именно нажимается. Codex работает в собственной песочнице
(`workspace-write`: запись только в рабочую папку), а инструменты рабочего
стола получает только вместе с проверкой внутри сервера (путь «Б»,
`jarvis/risk/serverGate.ts`). Про сеть Джарвис не ручается: доступ из
песочницы Codex задаётся настройками самого Codex, и обещать «без сети» здесь
значит обещать за чужой конфиг.

### Gemini: путь «Б» и политика его же движка

У Gemini CLI есть хук `BeforeTool`, и явный отказ он держит. Но на своём сбое
хук пропускает вызов — так написано в его документации («Other: Warning … the
interaction proceeds») и так замерено на Gemini CLI 0.64.0 20.10.2026: упавший
хук (код 1), хук с мусором вместо JSON и зависший хук — запись файла прошла во
всех трёх случаях. Правило Джарвиса «любой сбой — отказ» такой хук не держит,
поэтому Gemini идёт путём Codex, а не Claude Code:

- **Оболочки нет.** Она вычеркнута трижды: списком встроенных инструментов в
  настройках (`tools.core` — список разрешённых, новый инструмент следующей
  версии сам туда не попадёт), `tools.exclude` и запретом политики.
- **Политика на каждый запуск** (`jarvis/backends/geminiPolicy.ts`) — флагом
  `--admin-policy`, то есть на уровне администратора: выше настроек человека и
  настроек папки проекта. Белый список: запрещено всё, разрешены чтение и
  поиск в папках задачи, нужные задаче инструменты сервера Джарвиса и запись —
  только относительным путём или внутрь рабочей папки и папки результатов, без
  «..», без `.claude`/`.codex`/`.gemini`/`.agents` и без папки Джарвиса. Сам
  Gemini вдобавок не пишет вне своих рабочих папок («Path not in workspace»).
  Шаблоны путей — без повторителя за группой: такие Gemini отвергает как
  опасные, и правило выпадает целиком (проверка его же — `geminiAcceptsPattern`).
- **Сломанная политика — стоп.** Gemini на ней не останавливается, а работает
  без неё; Джарвис видит «Policy file error» в stderr и обрывает запуск сам.
  Есть политики администратора на машине (тогда Gemini игнорирует наши) или
  папка задачи переписывает сервер Джарвиса своим `.gemini/settings.json` —
  Gemini через Джарвиса там не работает вовсе.
- **Экран и браузер** — только через MCP-сервер Джарвиса с `JARVIS_TOOL_GATE`:
  каждый вызов проверяет `serverGate`, с тем же вопросом голосом. Сломанный
  `gate.json` — отказ и безопасному инструменту.
- **Только вход через Google.** Свой дом Gemini — `data/gemini`
  (`GEMINI_CLI_HOME`): там его вход и постоянные настройки
  (`jarvis/backends/geminiHome.ts`) — `enforcedType: oauth-personal`, кредиты
  Google при исчерпанной квоте не тратятся (`billing.overageStrategy: never`),
  статистика использования выключена, автообновление выключено. Ключи API и
  обходы через Vertex вычищены из окружения, браузер в безголовом запуске не
  открывается (`NO_BROWSER`).

Проверено на настоящем CLI `pnpm jarvis:gemini-check`: с подменённой моделью
(`--fake-responses-non-strict`, без входа и сети) — оболочки нет, запись в
папке задачи проходит, наружу, через «..» и в `.gemini` — отказ, безопасный
инструмент Джарвиса работает, «Купить» спрашивает человека и на «нет»
отказывает, сломанный `gate.json` — отказ; живьём, со входом человека, —
задача, конспект, учёба и разговор.

Цена: у Gemini в Джарвисе нет командной строки, а читать и писать он может
только в папке задачи, папке результатов и через инструменты Джарвиса.
Конспекты, учёба, документы и сайты от этого не страдают; программа, которую
надо собрать и запустить, — да.

## Незнакомая фраза: лестница голосового слоя

Прямая команда знает фразу в лицо. Всё, чего таблица не знает, раньше
кончалось «не нашёл» или уходило агенту на полминуты. Теперь лестница такая:

1. **На слух** (`jarvis/control/soundMatch.ts`). «Переключись на клад» —
   Claude: латиница читается по-русски, гласные сводятся, слова сравниваются
   с допуском. Уверенно — только когда нет близкого соперника.
   `switchTarget.ts` решает, куда: раздел или вкладка в активном окне
   («код» в приложении Claude — переключатель Code), потом окно, потом
   псевдоним программы и вкладка браузера.
2. **Разговор с руками.** Не нашлось или фраза незнакомая — её получает
   разговор. У него есть `screen_overview` (окна и что в активном можно
   нажать, с точными названиями) и руки: `switch_to`, `press_control`,
   `open_menu`, `press_keys`, `type_text`, `open_site`, `send_to_claude`,
   `claude_waiting`, `open_claude_session`, `new_claude_session`. Один-три
   вызова — секунды (живой прогон 30.09.2026: 3–5 с на ход).
3. **Агент** — для работы в несколько шагов: код, документы, поиск.

Руки исполняет сам Джарвис через мост разговора (`TalkBridge`, действие `ui`).
Модель их руками не жмёт: кнопки оплаты и отправки (`labelRisk`), кнопки
удаления и перезаписи, Enter (в мессенджере он отправляет) и Shift+Delete —
отказ с подсказкой, что человек может сказать сам. Исключение одно —
`send_to_claude`: получатель — Claude, а не человек.

Прямые команды для приложения Claude: «клод код», «клод чат», «напиши клоду
…» (текст уходит как сказан, в журнал — только длина), «кто ждёт ответа»,
«открой сессию …», «новая сессия в …», «прерви клода». «Прерви», а не
«останови»: слова остановки заняты самим Джарвисом.

## Почему слои устроены именно так

**Router не решает задачу.** Он отвечает только на вопрос «какие возможности и
какой backend нужны». Это позволяет ему быть маленьким, детерминированным и
проверяемым — и работать без локальной модели вообще.

**Локальная модель — оптимизация, а не зависимость.** `LocalRouterModel.refine`
возвращает `null` при любой проблеме: нет сервера, медленно, невалидный JSON,
модель решила ответить на вопрос вместо маршрутизации. У её ответа нет ни
одного поля, которым можно выдать разрешение, выбрать backend или понизить риск.

**Backend'ы — адаптеры, а не приложения внутри приложения.** Claude Code, Codex и
Gemini запускаются как официальные CLI в headless-режиме; Jarvis не хранит ключей, не
читает OAuth-токены и не переписывает агентов. Новый поставщик — это новый
адаптер, а не правки в ядре.

**Fallback только на отказ backend'а.** Если Claude Code отработал и честно
сказал «не смог, вот почему» — это ответ, а не повод спросить то же самое у
Codex. Переключение происходит на исчерпанном лимите подписки, на отсутствии
CLI, на упавшем процессе.

**Codex не подменяет Claude Code** (решение владельца 29.09.2026). У
пользователя Claude работает только Claude: исчерпанный лимит или сбой не
отдают работу Codex. У пользователя Codex (Claude Code не установлен или вход
не выполнен) Codex заменяет его целиком — с экраном через сервер Джарвиса;
свои `computer_use`, `browser_use` и плагины у Codex выключены и в работе, и в
разговоре. Названный голосом («отдай Кодексу») или в настройках Codex работает
как раньше.

**Gemini не подменяет ни Claude Code, ни Codex** — по тому же правилу: у
пользователя Claude или Codex исчерпанный лимит не отдаёт работу Google-аккаунту.
У того, у кого есть только Gemini, он заменяет их целиком — в задачах, в
разговоре, в конспекте лекций и в учёбе. Кто работает, человек выбирает во
вкладке «Агенты»; «первый готовый» — Claude Code, потом Codex, потом Gemini.

**Ошибка backend'а не роняет Jarvis.** Любой сбой адаптера превращается в
результат с `ok: false`, а не в исключение.

| `jarvis/context` | Состояние мира: активное окно, вкладка, проект, предыдущий результат |
| `jarvis/tasks` | Передний план / фон, пауза, отмена, модель прогресса |

| `jarvis/locale` | Язык режима: `tr(ru, en)` и таблицы на двух языках |
| `jarvis/desktop` | MCP-сервер рабочего стола: экран, окна, браузер, Blender, Krita, файлы результата; `launch.ts` — как его запустить |
| `jarvis/dialogue` | Разговор вторым потоком: живая сессия Claude Code или ходы Codex (`codexTalk.ts`, без оболочки, песочница «только чтение») и Gemini (`geminiTalk.ts`, только глаголы разговора) и их рычаги через мост к менеджеру задач |
| `jarvis/measure` | Трёхзначные проверки: прошло / не прошло / нечем мерить |
| `jarvis/observe` | Лента событий для окна логов, разбор прогонов |

| `jarvis/core.ts`, `jarvis/createJarvis.ts` | Оркестратор и его сборка |
| `app` | Приложение: главный процесс, трей, настройки, голосовой мост, оверлеи |

## Два языка

Язык режима задаёт, на каком языке Джарвис отвечает, какой голос звучит и на
каком языке слушает Whisper (`jarvis/locale/language.ts`). Понимание —
объединение обоих языков: слова остановки, «да/нет», команды, словарь
маршрутизатора и классификатор риска работают в любом режиме. Так красная
линия не зависит от настройки, а русские пользователи и так говорят
английские технические слова.

Только по-русски пока: правка диктовки («удали последнее слово») и живые
правки в Blender.

## Проверка голоса без микрофона

`pnpm jarvis:roundtrip` синтезирует фразы голосом Piper, распознаёт их Whisper
и пускает через тот же конвейер, что и живую речь (ослышки, отсев шума,
разбор). Синтез чище человека, поэтому результат — нижняя граница, но ломается
здесь то же, что у человека. Этот прогон нашёл, что линейная передискретизация
съедала шипящие («Stop» → «Top») и что Whisper на коротком звуке зацикливается
(«Silence. Silence. Silence.»); оба исправлены.
