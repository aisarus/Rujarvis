# Архитектура Jarvis

Rujarvis — самостоятельное приложение Electron. Он начинался как форк
[Interpreter Workstation](https://github.com/openinterpreter/interpreter-workstation),
но от его кода больше не зависит ни строкой: работу делают официальные CLI
Claude Code и Codex по подписке человека, а экран, браузер и файлы агент
получает от собственного MCP-сервера Джарвиса.

```
  микрофон ─► app/voiceBridge.ts ─► прямые команды (клавиши, окна, программы) ──► сразу
                    │
                    ├─► разговор: живая сессия Claude Code (jarvis/dialogue)
                    │        └─ рычаги: завести / поправить / остановить работу
                    │
                    └─► JarvisCore (jarvis/core.ts)
                          router ─► risk ─► tasks ─► BackendManager
                                                      ├─ Claude Code  + MCP рабочего стола
                                                      │               + хук красных линий
                                                      ├─ Codex        (песочница, без сети)
                                                      └─ локальная модель (если настроена)
```

Приложение (`app/`): трей, онбординг и настройки (`settingsWindow.ts`,
`ui/`), голосовой мост, оверлеи. Всё на диске — в одной папке
(`jarvis/setup/paths.ts`), язык — одна настройка (`jarvis/locale/`).

## Поток одной реплики

`JarvisCore.handleUtterance` выполняет ровно эту последовательность:

1. **Локальная проверка управляющих слов.** «Стоп», «отмена», «пауза»,
   «продолжай» обрабатываются синхронно, без модели и без сети. Ждать токены
   от большой модели, пока ассистент продолжает печатать в редакторе — самый
   быстрый способ потерять доверие пользователя.
2. **Маршрутизация.** `jarvis/router` определяет capabilities, backend, проект,
   риск и потолок разрешений. Правила детерминированы: без единой загруженной
   модели маршрутизация работает.
3. **Нормализация.** Приводит реплику к цели и ограничениям. Два инварианта
   держатся кодом, а не просьбой в промпте: нормализация может только *сужать*
   разрешения, и исходная реплика всегда доходит до сильного backend.
4. **Политика риска.** Классификация — чистая функция от конкретного действия.
   Текст модели может поднять класс, но никогда не понизить.
   Это первая проверка — по фразе. Вторая идёт на каждом вызове инструмента
   агентом (см. «Красные линии на инструментах» ниже).
5. **Отбор контекста.** Только то, чего касается эта реплика: релевантные
   записи памяти плюс состояние мира, если в реплике есть «это», «туда»,
   «продолжай». Полный дамп памяти в каждый запрос — это медленно, дорого и
   сбивает модель.
6. **Задача.** `TaskManager` запускает работу. Метод возвращается сразу: задача
   на пять минут не должна блокировать следующую фразу.
7. **Подтверждение голосом.** Строится из решения маршрутизатора — до того, как
   любая модель выдала первый токен. Оно никогда не утверждает, что работа
   сделана.
8. **Прогресс и результат.** Прогресс показывает действия, а не рассуждения.
   Экран получает полный ответ, голос — одно-три коротких предложения.

## Красные линии на инструментах

Фраза «разбери загрузки» безопасна, а `git push --force`, который агент
выполнит посреди этой работы по подсказке с прочитанной страницы, — нет.
Поэтому каждому запуску Claude Code даётся хук PreToolUse
(`jarvis/risk/gateHook.ts`, роль `gate` сборки `mcp.cjs`). Он переводит вызов
инструмента в действие для той же политики (`jarvis/risk/toolGate.ts`):

- команды оболочки — по шаблонам разрушительного и уходящего наружу;
- запись файла — по месту: системные папки опасны, `.claude`/`.codex` и данные
  Джарвиса чувствительны, рабочая папка, папка результатов и временная — обычны;
- кнопки браузера со словами оплаты и отправки, поля карт и паролей;
- запись навыка в общие навыки Claude Code, запуск исполняемого файла,
  перенос файла снаружи в папку результатов.

О чувствительном и опасном хук спрашивает человека голосом через файловый мост
(`jarvis/risk/gateBridge.ts`) и ждёт до минуты. Молчание, нечитаемый вызов,
любой сбой — отказ. Если хук поставить нельзя (нет `node` или сборки), агент
не получает оболочку, запись навыков и свою папку на запись.

Чего хук не видит: клик по координатам и нажатие элемента окна по номеру не
говорят, что именно нажимается. Codex работает в собственной песочнице
(`workspace-write`: запись только в рабочую папку) и десктопных инструментов не
получает. Про сеть Джарвис не ручается: доступ из песочницы Codex задаётся
настройками самого Codex, и обещать «без сети» здесь значит обещать за чужой
конфиг.

## Почему слои устроены именно так

**Router не решает задачу.** Он отвечает только на вопрос «какие возможности и
какой backend нужны». Это позволяет ему быть маленьким, детерминированным и
проверяемым — и работать без локальной модели вообще.

**Локальная модель — оптимизация, а не зависимость.** `LocalRouterModel.refine`
возвращает `null` при любой проблеме: нет сервера, медленно, невалидный JSON,
модель решила ответить на вопрос вместо маршрутизации. У её ответа нет ни
одного поля, которым можно выдать разрешение, выбрать backend или понизить риск.

**Backend'ы — адаптеры, а не приложения внутри приложения.** Claude Code и Codex
запускаются как официальные CLI в headless-режиме; Jarvis не хранит ключей, не
читает OAuth-токены и не переписывает агентов. Новый поставщик — это новый
адаптер, а не правки в ядре.

**Fallback только на отказ backend'а.** Если Claude Code отработал и честно
сказал «не смог, вот почему» — это ответ, а не повод спросить то же самое у
Codex. Переключение происходит на исчерпанном лимите подписки, на отсутствии
CLI, на упавшем процессе.

**Ошибка backend'а не роняет Jarvis.** Любой сбой адаптера превращается в
результат с `ok: false`, а не в исключение.

## Каталоги

| Каталог | Что внутри |
| --- | --- |
| `jarvis/backends` | `AgentBackend`, `BackendManager`, адаптеры Claude Code / Codex / OpenAI-совместимый, поиск CLI (`cliProbes.ts`) |
| `jarvis/router` | Определение capabilities, словари (`lexicon.ru.ts`, `lexicon.en.ts`), нормализация, опциональная локальная модель |
| `jarvis/risk` | Классы риска, политика подтверждений, хук красных линий на инструментах |
| `jarvis/memory` | Проекты, алиасы приложений, недавние задачи; файловое хранилище |
| `jarvis/context` | Состояние мира: активное окно, вкладка, проект, предыдущий результат |
| `jarvis/tasks` | Передний план / фон, пауза, отмена, модель прогресса |
| `jarvis/voice` | Обращение, слова остановки, устный ответ, распознавание (Whisper) и голос (Piper, `tts.ts`) |
| `jarvis/setup` | Пути (`paths.ts`), настройки (`settings.ts`), помощники онбординга |
| `jarvis/locale` | Язык режима: `tr(ru, en)` и таблицы на двух языках |
| `jarvis/desktop` | MCP-сервер рабочего стола: экран, окна, браузер, Blender, Krita, файлы результата; `launch.ts` — как его запустить |
| `jarvis/dialogue` | Разговор вторым потоком: живая сессия и её рычаги через мост к менеджеру задач |
| `jarvis/measure` | Трёхзначные проверки: прошло / не прошло / нечем мерить |
| `jarvis/observe` | Лента событий для окна логов, разбор прогонов |
| `jarvis/dota` | Отложенный эксперимент с оверлеем Dota 2, из приложения не вызывается |
| `jarvis/core.ts`, `jarvis/createJarvis.ts` | Оркестратор и его сборка |
| `app` | Приложение: главный процесс, трей, настройки, голосовой мост, оверлеи |

## Два языка

Язык режима задаёт, на каком языке Джарвис отвечает, какой голос звучит и на
каком языке слушает Whisper (`jarvis/locale/language.ts`). Понимание —
объединение обоих языков: слова остановки, «да/нет», команды, словарь
маршрутизатора и классификатор риска работают в любом режиме. Так красная
линия не зависит от настройки, а русские пользователи и так говорят
английские технические слова.

Только по-русски пока: правка диктовки («удали последнее слово») и живые
правки в Blender.

## Проверка голоса без микрофона

`pnpm jarvis:roundtrip` синтезирует фразы голосом Piper, распознаёт их Whisper
и пускает через тот же конвейер, что и живую речь (ослышки, отсев шума,
разбор). Синтез чище человека, поэтому результат — нижняя граница, но ломается
здесь то же, что у человека. Этот прогон нашёл, что линейная передискретизация
съедала шипящие («Stop» → «Top») и что Whisper на коротком звуке зацикливается
(«Silence. Silence. Silence.»); оба исправлены.
