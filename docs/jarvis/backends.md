# Backend'ы подписочных агентов

> Interpreter Workstation и говорил только по-русски. Текущее устройство — в

Jarvis не владеет ни одной моделью. Он владеет решением, кому отдать работу.

## Контракт

```ts
interface AgentBackend {
  readonly id: BackendId;
  readonly name: string;
  readonly capabilities: ReadonlySet<JarvisCapability>;
  checkAvailability(force?: boolean): Promise<BackendAvailability>;
  run(request: BackendRequest): BackendRun;
}
```

`run` возвращает поток событий и ровно один терминальный результат. Ошибка
адаптера — это результат с `ok: false`, никогда не исключение: сбой поставщика
не имеет права уронить процесс Jarvis.

## Claude Code

Запускается официальный `claude` в headless-режиме:

```
claude -p --output-format stream-json --verbose --permission-mode <mode> [--resume <id>]
```

Промпт уходит через stdin, а не в аргументах — длинная русская реплика не
должна упираться в ограничение длины командной строки Windows.

Jarvis **не** использует Anthropic API key, **не** читает OAuth-токены Claude и
**не** переписывает агента. Вход пользователь выполняет штатным способом Claude
Code. Jarvis проверяет только три вещи: установлен ли CLI, выполнен ли вход,
запускается ли он — переиспользуя для этого детектор самого Workstation
(`server/handlers/providers.ts`), а не заводя вторую копию списка путей.

### Разрешения

Режим выбирается кодом до старта модели, поэтому никакой текст модели не может
его расширить:

| Конверт задачи | `--permission-mode` |
| --- | --- |
| `edit: false` | `plan` — осмотреть и доложить, ничего не менять |
| риск safe/normal | `acceptEdits` |
| риск sensitive/dangerous | `default` — CLI спрашивает сам |
| `bypassPermissions` | только при явной настройке пользователя, и только для safe |

## Codex

```
codex exec [resume <thread>] --json --skip-git-repo-check --sandbox <level> [--cd <dir>] -
```

Вход — штатный «Sign in with ChatGPT» через Codex. Никакого скрейпинга
ChatGPT Web, никакого переиспользования чужих credentials.

| Конверт задачи | `--sandbox` |
| --- | --- |
| `edit: false` | `read-only` |
| обычная работа | `workspace-write` |
| `danger-full-access` | только при явной настройке, и только для safe |

Парсер понимает обе схемы событий: современную (`thread.started`,
`item.completed`) и старую (`{"msg": {...}}`), потому что какая придёт —
зависит от версии CLI на машине.

## Interpreter

Собственный runtime Workstation — единственный backend с доступом к экрану,
браузеру, окнам и системе. Задача, которой нужен `computer`, `browser`,
`vision`, `communication` или `system`, уходит туда независимо от настройки
coding-backend: Claude Code не умеет кликать по окну.

Runtime подключается через инжектируемый `InterpreterRuntimeDriver`, чтобы
реализация Workstation оставалась единственной, а ядро Jarvis — тестируемым.

## OpenAI-совместимый и локальный

Один адаптер на любой эндпоинт `/v1/chat/completions`: хостинг, Ollama,
LM Studio, сервер llama.cpp. Это последняя ступень fallback — без единой
подписки Jarvis всё равно отвечает — и клиент, которым пользуется опциональная
локальная модель-маршрутизатор. Инструментов у него нет: он рассуждает и пишет,
но не действует на компьютере.

## Выбор backend'а

`BackendManager.plan` строит упорядоченный список кандидатов:

1. Backend, названный вслух: «сделай это через Клод Код», «отдай это Кодексу».
2. Задача требует экрана, браузера или окон → `interpreter`.
3. Задача по коду → предпочтение из настроек, затем второй coding-backend,
   затем runtime.
4. Всё остальное → основной backend из настроек, затем runtime.

Исключение, названное вслух («не используй Клод»), убирает backend из всей
цепочки, а не только из первой позиции.

## Fallback

Переключение происходит только на отказе **самого backend'а**:

* исчерпан лимит подписки;
* CLI не установлен или вход не выполнен;
* процесс не запустился или умер, не выдав ничего.

Если backend отработал и честно сказал «не смог, вот почему» — это ответ.
Задать тот же вопрос другому поставщику не значит получить лучший результат,
поэтому Jarvis этого не делает. Таймаут тоже не повод: длинная задача обычно
просто длинная.

## Настройки

Раздел **AI Accounts** показывает для каждого backend'а: установлен, выполнен
ли вход, готов ли к работе, версия и путь к исполняемому файлу. Ни токенов, ни
паролей там нет и не будет — Jarvis их не видит.
