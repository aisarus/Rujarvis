# Статус MVP

Документ отвечает на один вопрос: что действительно проверено, а что пока
только написано. Он намеренно неудобный — «собирается» и «работает» это разные
утверждения.

Все проверки ниже выполнялись в Linux-контейнере. Windows-машины в этой сессии
не было и микрофона тоже. Claude Code и Codex CLI в контейнере есть и
запускаются по-настоящему: Claude Code доходит до ответа модели, Codex — нет,
его эндпоинт закрыт прокси.

Ограничение среды, о котором стоит знать: скриншоты и запись видео в Electron
под xvfb здесь не работают (это же ломает и штатный захват видео в тестовой
обвязке upstream). Поэтому визуальных подтверждений нет — только проходящие
прогоны.

### Замеры распознавания

Русские фразы синтезированы Piper и поданы в Whisper (CPU, int8,
однопоточная сборка WASM):

| Фраза | tiny | base |
| --- | --- | --- |
| «Джарвис, посмотри почему билд не собирается» | «Жарвис, посмотри почему бельт не собирается» | «Жарвис, посмотри, почему бильд не собирается» |
| «Закрой это окно» | «закрои и такно» | «закрой и так, но» |
| «Стоп» | «Стоп» | «Стоп» |

**Эти цифры не измеряют качество русского Whisper.** Та же `base` на реальной
человеческой речи (английские тестовые записи из архива модели) расшифровала
обе фразы дословно и без ошибок. Разница — в синтезированном звуке и в простой
линейной передискретизации 22050 → 16000 Гц, а не в модели. Настоящая проверка
русского требует живого микрофона на Windows и в этой сессии не делалась.

Из замеров всё же следует одно практическое решение: `small` втрое медленнее
`base` и точнее на этом материале не оказалась, поэтому по умолчанию стоит
`base`.

## Что дал живой прогон

Запуск всего конвейера против настоящих CLI нашёл пять вещей, которых модульные
тесты дать не могли. Все исправлены, на каждую есть регрессионный тест.

1. **Ложное «вход не выполнен».** Проверка файла учётных данных говорила «не
   авторизован», пока CLI отвечал за четыре секунды. Так устроены
   host-managed установки, ключи из переменных окружения и корпоративные
   шлюзы. Авторизация стала трёхзначной, состояние «неизвестно» разрешает
   запуск: ошибочный отказ блокирует рабочий backend навсегда, ошибочная
   попытка стоит одной быстрой ошибки с понятным текстом.
2. **Отрицание перетекало через границу предложения.** В «…только ничего не
   меняй. Через Клод Код.» частица «не» относится к «меняй», но читалась как
   исключение Claude Code — и работа уходила Кодексу, то есть ровно наоборот.
   Теперь отрицание разрешается внутри клаузы.
3. **Каждая shell-команда рисовалась дважды** в списке прогресса.
4. **Codex зависал на недоступной сети.** Он повторяет попытки, переключает
   транспорт и ждёт сеть, которой нет, без собственного терминального
   события. Прогон висел до таймаута — 90 секунд тишины и никакого fallback.
   Теперь серия попыток подряд завершает запуск с внятной причиной за 13
   секунд, и менеджер уходит на другой backend.
5. **Названный вслух backend отменял fallback.** «Отдай Кодексу» строило
   цепочку `[codex, interpreter]` — без Claude Code, вопреки пункту 25
   задания. И «что делает файл policy.ts» не считалось задачей по коду, из-за
   чего уезжало в десктопный runtime, который репозиторий читать не умеет.

## Что написано, но не проверено вживую

| Что | Почему не проверено | Чем рискуем |
| --- | --- | --- |
| Управление окнами, мышью, клавиатурой | нет Windows-десктопа | код Workstation не менялся; Jarvis только маршрутизирует туда задачи |
| Браузер и Playwright | то же | то же |
| `install.ps1` целиком | нет Windows | синтаксис и чистые функции проверены; winget, сборка и ярлык — нет |
| Push-to-talk, трей, оверлей | требует запущенного Electron | UI-слой ещё не подключён, см. ниже |
| Всегда включённое прослушивание | требует микрофона | детектор wake word покрыт тестами на тексте |

## Что ещё не сделано

1. **Подключение UI.** Раздел AI-аккаунтов готов и проверен в настоящем
   приложении. Осталось связать: глобальную горячую клавишу с
   `pressPushToTalk`/`releasePushToTalk`, оверлей со `status`, пункт в трее и
   переключатель backend'ов (нужна персистентность настроек Jarvis).
2. **Захват звука.** `VoiceSession` принимает интерфейсы `AudioCapture` и
   `Transcriber`; реализация поверх существующего аудиоконвейера Workstation не
   написана.
3. **Установка русского голоса при онбординге.** Скрипт сообщает о голосе, но
   ставит его менеджер моделей приложения при первом произнесении.
4. **Живая проверка русского ASR** на настоящей речи под Windows.
5. **Живой прогон Codex до ответа модели.** Запуск, аргументы и путь ошибки
   проверены; до ответа дойти нельзя — прокси контейнера блокирует его
   эндпоинт.

## Сценарии приёмки

Каждый сценарий из задания существует как тест в `jarvis/core.vitest.test.ts` и
проходит весь конвейер — управляющие слова, маршрутизация, нормализация,
политика риска, отбор контекста, задачи, устный ответ. Подменены только
backend'ы.

| Тест | Сценарий | Статус |
| --- | --- | --- |
| A | «Открой Chrome» | конвейер и драйвер runtime проверены; исполнение ждёт Windows |
| B | вкладка GitHub, репозиторий Aegis | то же |
| C | «Закрой это окно» — контекст переднего окна доезжает | то же |
| D | «Посмотри что на экране» — vision, ответ по-русски | то же |
| E | «В проекте Aegis … через Claude Code» — cwd, session id, короткий пересказ | конвейер проверен; живой CLI не запускался |
| F | «Теперь через Codex», «не используй Клод» | то же |
| G | «А пока открой Телеграм» во время долгой задачи | проверено полностью |
| H | «Стоп» — мгновенно, только передний план | проверено полностью |

G и H проверены полностью, потому что это целиком логика оркестрации: ни
десктоп, ни подписка для них не нужны.

## Definition of Done — чего не хватает

Заявленная готовность — управление Windows обычной русской речью по цепочке
voice → reasoning → browser → computer → filesystem → shell → Claude Code/Codex
→ TTS.

Собраны и проверены: обе стороны речи, маршрутизация, нормализация, политика
риска, память, состояние мира, оркестрация задач, все четыре адаптера
backend'ов и мост к runtime Workstation. Ядро собирается одним вызовом
`createJarvis`.

Не хватает: вызвать его из UI, подключить микрофон к распознаванию (пункты 1–2
выше) и проверить всё это на настоящей Windows-машине с подпиской.
